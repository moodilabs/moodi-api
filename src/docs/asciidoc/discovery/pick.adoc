== 사진 추천 (Pick)

사진 1장과 지역을 입력받아 무드가 비슷한 스팟을 추천하는 API입니다.

=== 사진 업로드 방식

서버는 사진 파일 본문을 받지 않습니다. 클라이언트가 발급받은 서명 URL로 스토리지에 직접 업로드하고,
서버에는 그 결과로 받은 `imageKey`만 전달합니다.

[source]
----
1. GET /api/v1/picks/upload-url   → uploadUrl, imageKey 발급
2. PUT {uploadUrl}                → 클라이언트가 사진을 직접 업로드
3. POST /api/v1/picks             → imageKey와 지역을 담아 추천 요청
----

업로드 요청(2단계)에는 **발급받을 때 보낸 것과 동일한 `Content-Type` 헤더**를 실어야 합니다.
서명에 형식이 포함되어 있어 다른 형식으로 올리면 스토리지가 거부합니다.

업로드된 사진은 비공개로 보관되어 `imageKey`만으로는 열람할 수 없습니다.

=== 업로드 URL 발급

사진은 **1장**만 올릴 수 있고, `image/jpeg` · `image/png` · `image/heic` 형식의 **10MB 이하** 파일만 허용합니다.
`Authorization: Bearer {accessToken}` 헤더가 필요합니다.

=== 스팟 추천

업로드한 사진의 무드와 비슷한 스팟을 선택 지역 안에서 **최대 5개** 추천합니다.
생성과 결과 조회를 겸하므로 이 요청 하나로 결과 화면까지 갈 수 있습니다.

지역은 **1개 이상 5개 이하**로 고르고, 자동완성 결과에서 고른 값만 보냅니다.
지역명은 **검색 API가 돌려준 영문 표기 그대로**(`Seoul` · `Seongdong-gu`) 보내면 됩니다.
한국어로 보내도 동작하며, 동·면은 사전이 없어 한국어 표기를 씁니다.
상위 지역과 그 하위 지역을 함께 보내면 **서버가 상위 하나로 접습니다.**
(예: `성수동, 성동구, 서울` + `서울` → `서울` 하나)

정렬은 사진과 스팟의 **무드 벡터 유사도 내림차순**입니다.
무드 분석 이력이 없는 스팟은 유사도를 잴 수 없어 후보에서 빠집니다.

==== 추천 결과가 없는 경우

오류가 아닙니다. `spots`가 빈 배열로 내려가고, **이때만** `fallbackSpots`가 채워집니다.
대체 추천은 지역 조건을 풀고 무드 태그가 겹치는 스팟 중에서 뽑은 것으로,

=== 추천 결과 재조회

저장된 추천 결과를 다시 조회합니다 (`DSC-05`). 결과 화면을 다시 열거나 루트 편집에서 돌아올 때 씁니다.

**사진을 다시 분석하지 않습니다.** 같은 사진이라도 분석 결과가 매번 미세하게 달라질 수 있어,
재조회 때마다 순서가 바뀌면 "모달 종료 시 기존 결과 유지" 요구를 만족할 수 없습니다.
그래서 순서는 저장된 순위를 그대로 쓰고, **스팟 내용과 저장 여부만 조회 시점 값으로** 채웁니다.

[NOTE]
====
추천 이후 비활성으로 내려간 스팟은 결과에서 빠지므로 **개수가 추천 당시보다 적을 수 있습니다.**
빈 자리를 다른 스팟으로 메우지 않습니다. 재조회는 그때 본 목록을 되살리는 것이지 새로 추천하는 것이 아닙니다.
====
